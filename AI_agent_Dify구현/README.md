# CLAUS — CLaim AUtomobile Support

> 자동차 사고 손해사정 업무 보조 AI Agent  
> 생성형AI와비즈니스 수업 팀 프로젝트 (팀404) · 국민대학교 2026

---

## 프로젝트 개요

손해사정사는 자동차 사고 발생 시 약관 검토, 유사 판례 탐색, 보고서 작성을 수동으로 수행해야 합니다. 계약 연도별 약관 차이, 방대한 판례 데이터, 다양한 사고 유형별 검토 항목이 업무 부담을 가중시키며, 일반 LLM은 보험사 내부 약관과 업무 지식을 반영하지 못한다는 한계가 있습니다.

**CLAUS**는 사고 정보를 입력하면 약관·판례·핵심 쟁점을 자동 분석하여 세 가지 유형의 손해사정 보고서를 생성하는 Dify 기반 AI Agent입니다.

---

## 핵심 기능

| 기능 | 설명 |
|------|------|
| **소멸시효 자동 계산** | 상법 제662조 기준 3년, 사고일 입력 시 잔여 시효 자동 산출 및 상태 분류 (시효 여유/주의/임박/경과) |
| **약관 조건부 라우팅** | 계약 연도(2023/2025) × 보험사(삼성화재/현대해상/KB손해보험) 조합으로 해당 DB에 자동 라우팅 |
| **판례 다중 소스 병렬 검색** | 교통 손해사정 판례 DB + 금융감독원 분쟁사례 DB + Tavily 실시간 웹 검색(대법원·금감원 등) 병렬 실행 |
| **입력 품질 자동 검증** | 사고 경위·손해 유형·피해 내용·핵심 쟁점 4개 항목 평가, 2개 이상 미달 시 보고서 미생성 |
| **보고서 3종 자동 생성** | 약관 보고서 / 판례·분쟁 보고서 / 핵심 쟁점 보고서 선택 생성 |
| **Word 파일 자동 저장** | LLM 출력 → Word 변환 → Dropbox 업로드 → 다운로드 URL 반환 |

## 서비스 흐름

```
입력 (사고 정보)
    │
    ▼
입력 전처리 & 품질 검증
    │
    ├─ 품질 미달 → "정보부족" 출력
    │
    ▼
사건 분석 (사고 유형, 담보 후보, 소멸시효)
    │
    ▼
다중 RAG 병렬 검색
    ├── 약관 DB (보험사 × 연도 조건부 라우팅)
    ├── 판례·분쟁사례 DB
    └── Tavily 실시간 웹 검색
    │
    ▼
보고서 유형 분기 (약관 / 판례 / 핵심쟁점)
    │
    ▼
최종 보고서 생성 → Word 파일 저장 (Dropbox)
```

## 기술 스택

| 구분 | 내용 |
|------|------|
| Agent 프레임워크 | [Dify](https://dify.ai) (No-code Workflow) |
| LLM | GPT-5-mini (검색어 선정, 품질 검증, 보고서 생성) |
| 실시간 검색 | Tavily Search API (최대 5건, 대법원·금감원 우선) |
| RAG DB | Dify 내장 벡터 DB (파일별 분리 구성) |
| 출력 저장 | Dropbox API (Word 파일 자동 업로드) |
| 워크플로우 형식 | YAML (Dify export) |

## 입력 파라미터

| 파라미터 | 타입 | 필수 | 설명 |
|----------|------|------|------|
| `report_type` | select | ✅ | 약관 / 판례 / 핵심 쟁점 |
| `insurer` | select | ✅ | 삼성화재 / 현대해상 / KB손해보험 |

| `accident_date` | date | ✅ | 사고 일자 (소멸시효 계산용) |
| `accident_description` | textarea | ✅ | 사고 내용 (핵심 정보 추출) |
| `claimed_amount` | number | ➖ | 청구 금액 (보험금 계산용) |
| `uploaded_files` | file | ➖ | 영수증, 진단서 등 첨부 파일 |

## 지식베이스 구성 상세

### 청킹 전략

| 파일 | 청킹 방식 | 청크 수 | 구분자 |
|------|----------|---------|--------|
| 표준약관 23/25년 | 조항 단위 (`청크번호:` 라인) | 365 / 324 | 라인 파싱 |
| 삼성화재·현대해상·KB 약관 | `## 조항명` 헤더 단위 | 90 / 114 / 142 | `<<<CHUNK>>>` |
| 금융감독원 분쟁사례 | 사례 단위 | 41 | `<<<CHUNK>>>` |
| 업무 지식 베이스 | 섹션 단위 (`[청크ID]`) | 56 | 메타데이터 포함 |
| 판례 선별 | 판례 단위 (`## N.`) | 9 | 헤더 |

> **Dify 설정 권장**: 약관·분쟁사례 파일은 "구분자 기반 청킹"에서 `<<<CHUNK>>>`를 구분자로 지정. 표준약관 txt 파일은 "고정 길이 청킹" 대신 라인 단위 파싱 권장.

### 보험사별 약관 DB 라우팅 로직

```
입력: insurer, contract_year
    │
    ├── contract_year 포함 2025 → 표준약관_25 DB
    └── else → 표준약관_23 DB
    │
    ├── insurer == 삼성화재 → 삼성화재 약관 DB
    ├── insurer == 현대해상 → 현대해상 약관 DB
    └── insurer == KB손해보험 → KB손해보험 약관 DB
```

## LLM vs Agent 비교

| 항목 | 일반 LLM | CLAUS Agent |
|------|----------|-------------|
| 소멸시효 계산 | 날짜 혼동, 계산 오류 가능 | 코드 분리 실행으로 정확도 향상 |
| 최신 정보 반영 | 실시간 검색 불가 | Tavily로 대법원·금감원 최신 정보 반영 |
| 약관 DB 선택 | 다중 파일 혼재 시 오염 가능 | 보험사·연도 조건으로 DB 자동 분기 |
| 할루시네이션 | 정보 부족해도 그럴듯한 답변 생성 | 입력 품질 검증 후 부족 시 보고서 미생성 |
| 출력 형식 | 텍스트 응답 | Word 파일 자동 생성 및 다운로드 URL 제공 |

## 기대 효과 및 한계

**기대 효과**
- 보고서 초안 작성 시간 단축으로 업무 효율 향상
- 약관 검토 누락 방지 (체크리스트 기반 자동 확인)
- 판례·분쟁사례 기반 근거 중심 판단 지원
- 일관된 보고서 포맷으로 업무 표준화

**한계점**
- 지식베이스 DB는 지속적인 업데이트 필요 (최신 약관·판례 미반영 가능)
- 복잡한 법률 판단은 반드시 전문가 검토 필요
- 현재 자동차 사고에 한정 (화재·상해 등 타 사고 유형 미지원)
- AI 판단은 보조 수단이며 보험금 지급 여부·과실비율 확정 불가
